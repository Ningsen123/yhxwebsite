# 网络问题排查与解决记录

**日期**: 2026年5月19日  
**问题**: Git推送GitHub超时，无法部署代码到Cloudflare Pages

---

## 一、问题现象

### 1.1 错误信息
```
fatal: unable to access 'https://github.com/Ningsen123/yhxwebsite.git/': 
Failed to connect to 127.0.0.1 port 1082 after 3 ms: Couldn't connect to server
```

### 1.2 影响范围
- Git推送（HTTPS方式）❌
- Git推送（SSH方式）❌
- GitHub网页访问 ❌
- GitHub API访问 ✅

---

## 二、问题原因

### 2.1 根本原因
系统配置了本地代理（127.0.0.1:1082），但代理服务未运行或端口不通。

### 2.2 代理来源
- 可能是V2Ray、Clash或其他代理软件
- 代理配置在环境变量和git全局配置中

### 2.3 检查发现的配置

| 配置项 | 值 | 状态 |
|--------|-----|------|
| http_proxy | 127.0.0.1:1082 | 需要清除 |
| https_proxy | 127.0.0.1:1082 | 需要清除 |
| git http.proxy | 127.0.0.1:1082 | 需要清除 |
| git https.proxy | 127.0.0.1:1082 | 需要清除 |
| SSH known_hosts | 无GitHub记录 | 需要添加 |

---

## 三、解决方案

### 3.1 清除代理配置

```bash
# 清除环境变量代理
unset http_proxy
unset https_proxy
unset HTTP_PROXY
unset HTTPS_PROXY
unset all_proxy
unset ALL_PROXY

# 清除git全局代理
git config --global --unset http.proxy
git config --global --unset https.proxy
```

### 3.2 添加GitHub到SSH known_hosts

```bash
ssh-keyscan github.com >> ~/.ssh/known_hosts
```

### 3.3 切换到SSH认证

```bash
# 切换远程地址为SSH
git remote set-url origin git@github.com:Ningsen123/yhxwebsite.git
```

### 3.4 验证SSH连接

```bash
ssh -T git@github.com
# 预期输出: Hi Ningsen123! You've successfully authenticated...
```

### 3.5 推送代码

```bash
git push origin main
```

## 五、预防措施

### 5.1 检查代理配置
```bash
# 检查环境变量
echo $http_proxy
echo $https_proxy

# 检查git配置
git config --global --get http.proxy
git config --global --get https.proxy
```

### 5.2 临时禁用代理（不修改配置）
```bash
# 临时取消代理（当前终端有效）
unset http_proxy https_proxy

# 或者只对git禁用
git -c http.proxy="" push origin main
```

### 5.3 永久禁用代理
```bash
# 从git配置中删除
git config --global --unset http.proxy
git config --global --unset https.proxy
```

### 5.4 使用SSH替代HTTPS
```bash
# 切换到SSH（推荐）
git remote set-url origin git@github.com:用户名/仓库名.git

# SSH无需代理，更稳定
```


## 七、注意事项

1. **代理软件**：如果使用V2Ray/Clash，关闭软件后需要清理代理配置
2. **SSH密钥**：确保~/.ssh/id_rsa或id_ed25519已添加到GitHub
3. **网络环境**：公司网络可能有防火墙，需要使用VPN或代理
4. **代理恢复**：如果需要恢复代理，重新设置环境变量即可
